# Memory comparison

Measured on November 4, 2026 US/Pacific (November 5 UTC), on Linux
7.3.1-1-cachyos x86_64 with Python 3.14.9 and 12 available CPUs.

Rust: official GitHub [v0.99.24](https://github.com/pbtrung/soju-rs/releases/tag/v0.99.24)
x86_64 GNU and musl archives, SHA-256 verified. The tagged source matches
local `main` at `6b9bf15898da370b7a00e14025a72829de342f71`.

C: root debug binary and existing `build/gcc-release/soju`, both v0.99.0,
in the clean tracked checkout at `29943811f9f5eae9ac208131e1065fa035738b0e`.
The existing binaries were measured without rebuilding them.
The debug build uses `-O0 -g3` and debug mimalloc; release uses `-O2 -g`
and secure mimalloc. Both use mimalloc 3.5.4, OpenSSL 3.6.5, libcurl
8.23.0, libuv 1.53.0, and SQLite 3.54.1.

Fresh SQLite databases; identical TCP, WebSocket, and admin listeners; one user and one authenticated TCP client; no upstream networks.
SOJU_LOOPS and TOKIO_WORKER_THREADS set to the same worker count. Measurements taken after a 0.5 second settling delay per phase.
RSS and PSS measured from /proc; values below are MiB. Single runs per configuration, not a sustained workload or leak test.

The logged-in phase includes admin account creation and SASL PLAIN login.
Worker settings match event-loop counts, not total thread counts: C also
starts libuv worker threads for password hashing. All test processes were
stopped after their measurements.

Raw samples are in [memory-2026-11-04.json](memory-2026-11-04.json).
Those original samples use KiB for memory fields and omit the `repeat` and
`RssShmem` fields now included by the reusable harness.

At four workers after login, the C debug and Rust GNU mimalloc mappings each had 10,252 KiB resident. C libcrypto.so.3 had 5,024 KiB RSS and about 1,095 KiB PSS.
The C release did not improve RSS in this measurement, so debug overhead does not explain the observed gap by itself.
Larger virtual stack reservations should not be interpreted as fully resident RAM.

RSS counts resident shared pages in full for each process. PSS divides
them among the processes sharing them, so its values depend on other
processes running on the host. These samples show higher C RSS and lower
C PSS; they do not establish an inherent language advantage or identify
every allocation. The library mappings explain a substantial part of the
RSS difference, but were not isolated by rebuilding dependencies.

## Reproducing

Use Linux with readable `/proc/<pid>/smaps` and Python 3. Each `soju` must
have its matching `sojuctl` alongside it. The harness starts only the
supplied executables, creates fresh databases for every sample pair, and
keeps configs, logs, mappings, binary hashes, and JSON results in a new
output directory. Paths must not contain whitespace. Default loopback
ports 18670 and 18671 must be free; override them with `--irc-port` and
`--ws-port` when necessary.

Download and verify the Rust archives from the linked release, then run
from the repository root, adjusting the extracted binary paths:

```sh
cmake --preset gcc-release
cmake --build --preset gcc-release
python3 tools/bench-memory.py \
  --binary c-debug=./soju \
  --binary c-release=./build/gcc-release/soju \
  --binary rust-gnu=/tmp/rust-gnu/soju \
  --binary rust-musl=/tmp/rust-musl/soju \
  --workers 4 12 --repeat 3
```

`./soju` in the original run was an existing debug build. To build a new
debug binary, use `gcc-debug` and pass `./build/gcc-debug/soju` instead.
The original measurements used one repetition; use several repetitions
and a longer `--settle` delay to assess variation.

The reusable harness was subsequently validated against all four binaries
at both worker counts: eight successful process runs and 16 samples.
Those validation samples varied from the original run, including roughly
2 MiB differences in some Rust samples. The table retains the original
observations rather than selecting the lowest measurements.

The verified Rust archive SHA-256 values were:

- GNU: `3e027421544ca351066a81333111f2ed6528210cffa97e9b966c9d8f374bb813`
- musl: `03bacc0e98328b31d0eb02059da1929a37934708528c160f8c7bb0ef7d2b7d6d`
