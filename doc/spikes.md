# Phase 0 report: bootstrap and spikes

Phase 0 is complete (2026-10-29): every dependency builds in every mode,
the five spike risks of PLAN.md section 3 are resolved by the programs
below (kept as CTest tests until production code replaces them), and the
`hello` binary plus all tests pass in every target × compiler × mode cell
(see "Validation").

The dependency versions are listed in `deps/VERSIONS`, with URLs and
SHA-256 hashes in `deps/versions.cmake`. OpenSSL is the system library,
linked dynamically (3.6.5 on Arch, 2026-10-29); only the MSan build
compiles the same version from source, instrumented and without assembly.

## Executable experiments

Phases 8 and 9 replaced libwebsockets with an in-tree HTTP server and
libcurl (PLAN.md decisions 11 and 12): `spike_lws`, `spike_tls`,
`spike_http_client` and `lws-address-size.patch` were removed then. Their
findings are kept below for the record.

- `hello` includes the public dependency headers as C23 and exercises the
  linked libraries, including cmocka and yyjson.
- `spike_lws` consumes a known PROXY header from a socket pair, adopts the
  remaining HTTP stream and checks that client metadata reaches dispatch.
  This tests socket handoff, not a PROXY parser. Avoid reading beyond the
  PROXY header: the descriptor adoption API has no pre-read buffer field.
- Foreign libuv loop shutdown requires `lws_context_destroy`, draining
  the loop, and a final destroy call if `pcontext` is still non-null.
  `spikes/support.h` asserts that finalization clears the context pointer
  and that `uv_loop_close` succeeds.
- `spike_tls` obtains the vhost SSL_CTX through the server verification
  setup callback. The callback installs a generated certificate and key;
  the same context then accepts a replacement certificate. A memory-BIO
  handshake without SNI checks the replacement serial, HTTP/1.1 ALPN and
  acceptance of a self-signed client certificate. An adopted TLS server
  must use `CONTEXT_PORT_NO_LISTEN_SERVER`, not `CONTEXT_PORT_NO_LISTEN`.
- `spike_http_client` connects to a numeric loopback address while sending
  an unrelated Host name, with automatic redirects disabled: DNS filtering
  (refusing internal IPs) is done by resolving and checking addresses
  ourselves before connecting, and again for each redirect. TLS SNI
  behaviour was inspected in lws's `openssl-client.c`. A second request
  the server never answers is ended by a libuv timer calling
  `lws_set_timeout(wsi, PENDING_TIMEOUT_USER_OK, LWS_TO_KILL_SYNC)`
  within ~1 s: lws re-arms its own client timeouts with the context-wide
  `timeout_secs` at each stage, so a per-request `lws_set_timeout()` set
  at connect time doesn't last, and `LWS_TO_KILL_ASYNC` never closed the
  connection. Production code keeps one timer per request.
- `spike_bcrypt` verifies a published bcrypt vector with `$2a$`, `$2b$`
  and `$2y$` prefixes, hashes made by Go soju's library
  (`golang.org/x/crypto/bcrypt`) and by soju-rs's (`bcrypt` 0.19.3, `$2a$`
  and `$2b$`), and generates `$2a$10$` salts, the format soju-rs writes.
  In the other direction, `$2a$` and `$2b$` hashes generated by libxcrypt
  verify with both Go's `CompareHashAndPassword` and Rust's
  `bcrypt::verify` (checked once, with those programs).

## Dependency fixes

The spikes exposed defects in the pinned dependencies. Source patches
are applied in every build mode, and their contents participate in the
dependency cache key. Sanitizer checks remain enabled.

- `lws-address-size.patch`: the Unix interface lookup cast a caller's
  `sockaddr_in` to the larger IPv4/IPv6 union. Parsing a numeric IPv4
  interface overwrote the stack. Parse into a full union, check the address
  family and destination size, then copy only the matching sockaddr.
- OpenSSL calls its stack, hash and sparse-array callbacks through
  function pointers cast to generic types, which Clang's UBSan `function`
  check rejects. While OpenSSL was vendored and built with the sanitizers,
  the dependencies were built with `-fno-sanitize=function`. The system
  OpenSSL isn't instrumented, so that exception is gone: every dependency
  we build keeps the full UBSan checks.

## Validation

At `fcaef41` (phase 1 included), all tests pass in:

| Target | GCC 16.2 / Alpine GCC 15.2 | Clang 23.1 |
|--------|---------------------------|------------|
| gnu (Arch, local and Docker) | debug, asan, tsan, release, ubsan-trap, valgrind | debug, asan, msan, tsan, release, ubsan-trap, valgrind, fuzz (seed replay) |
| musl (Alpine edge, Docker) | debug, release, ubsan-trap, valgrind | debug, release, ubsan-trap, valgrind |

Sanitizer runtimes don't support musl (PLAN.md 3.1); valgrind on Arch
needs `glibc-debug` (installed in `docker/Dockerfile.gnu`). Alpine edge
ships OpenSSL 3.5.9.

## Reproduction

Run `tools/ci.sh -j 4 gcc-debug gcc-asan clang-debug clang-asan` for the
commit checks. Run `tools/docker-test.sh gnu` and
`tools/docker-test.sh musl` for the native target matrices. Each default
Docker run pulls and rebuilds a fresh image; `SOJU_DOCKER_REUSE=1` reuses
an existing image for local iteration. Build outputs and test logs belong
under `build/` and are not committed.
